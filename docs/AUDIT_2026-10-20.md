# SolarDeck Full Repository Audit — 2026-10-20

Written 2026-10-20 04:13 UTC in the Pi harness by openrouter/deepseek/deepseek-v4.1-flash-1017

Scope: every tracked file (56), all 11 docs (7,202 lines), KiCad/netlist/PCB, gerbers,
STL, OpenSCAD, firmware, daemons, CI, and the verification suite. `python3 scripts/verify_all.py`
passes 9/9 in 1.7 s.

**Headline:** the *documentation* is far ahead of the *artifacts*. The docs describe a 61-line BOM,
6-layer routed board, and a manufacturable chassis. The repo contains 20 netlist components, an
unrouted PCB, gerbers that are bare pad flashes, and a 58-triangle STL. Everything currently green
in CI is a structural regex check, not a design check. Treat V1 as **architecture + narrative
complete, engineering ~5% complete** — and fix the sentence that says otherwise.

## 1. Blockers (must resolve before any fabrication order)

### B1. "Ready for fabrication" is false — artifacts are placeholders
| Artifact | Reality | Doc claim |
| :--- | :--- | :--- |
| `hardware/*.kicad_sch` (4 sheets) | 21 symbols total, **0 wires**; root sheet 0 symbols | full carrier board |
| `hardware/solardeck-carrier.net` | **20** components | 61 BOM line items |
| `hardware/solardeck-carrier.kicad_pcb` | 24 footprints, **0 nets, 0 track segments** | 6-layer routed stackup, 100 Ω/50 Ω controlled |
| `production/solardeck_gerbers.zip` | ~9 KB per Cu layer = pad flashes + outline only | fab-ready gerbers |
| `production/solardeck_chassis.stl` | **58 triangles**, 2,984 B | SLS/CNC enclosure with gasket groove, ports, inserts |

`verify_all.py` prints *"SolarDeck V1 is mathematically & structurally ready for fabrication."*
Recommendation: change that line to `"Structural consistency verified — NOT a design sign-off"`,
and add a hard gate that fails whenever netlist component count ≠ BOM row count. That single
assertion catches B1, B5 and most future drift.

### B2. TMUX1575 is a **4-channel** switch, not 8-channel
Datasheet: 4× SPDT, 16-bump DSBGA (YCJ), 1.4 × 1.4 mm. It cannot isolate the 6 display lines
(`SPI_MOSI/MISO/SCLK/CS/HRDY/RESET`) claimed in `docs/HARDWARE_SPEC.md:110-112` and the specs
matrix. Also, the BOM part number `TMUX1575PWR` (`docs/BOM_COST_ESTIMATE.md:15`) implies a PWR/TSSOP
package that does not exist for this device.
Fix: use **2× TMUX1575** (8 channels, 8 lines available) or a 6+ channel 2:1 part, correct the BOM
PN, and add a netlist assertion that every EPDC line passes through a switch channel.

### B3. The MIPI-DSI video path has no signal chain that reaches an E-Ink panel
`docs/HARDWARE_SPEC.md:125` routes CM4 DSI → **SN65DSI83** (DSI→LVDS) or CrossLink-NX / IT8961.
E-Paper panels have no LVDS input; they need a TCON + EPDC. Pick one and draw it:
IT8961/IT8951-with-DSI-front-end, or an FPGA TCON that emits the source-driver timing.
Until then the 24 FPS claim is unsupported — and `docs/OFFGRID_TACTICAL_SENSORS.md:248` itself says
e-paper "cannot switch … at 30–60 FPS".

### B4. Mechanical stackup does not close — two independent arithmetic failures
* `docs/MECHANICAL_FIT_AND_ENCLOSURE_WORKFLOW.md:82` sums to **12.55 mm** device thickness.
  `CHASSIS_DEPTH = 9.8` in `hardware/enclosure/solardeck_chassis.scad:12`, and
  `docs/HARDWARE_SPEC.md:1046` says "Total Internal Cavity Depth: 6.0 mm". 12.55 > 9.8 > 6.0.
  With a 12.55 mm build the device is ~2.8 mm thicker than every other doc states.
* **RESOLVED 2026-10-20 (ADR-008):** chassis re-derived to **232.0 × 170.0 × 14.0 mm**, cavity 12.5 mm; stackup branch 12.35 mm. Original finding kept: workflow said **227.7 × 165.8 mm** glass, chassis was **227.0 × 165.0 mm**,
  display aperture is 209.0 × 157.0 mm. The panel is *larger than the chassis it must live in*.
  Mass re-derived to 620 g.

### B5. Three mutually exclusive solar architectures are all "live"
| Source | Design | Power |
| :--- | :--- | :--- |
| `docs/BOM_COST_ESTIMATE.md:20` | single IXYS SM141K06L strip, $3.50 | 0.15 W |
| `docs/HARDWARE_SPEC.md:189-197` (§2.28) | dual-bezel IBC, 2 × 215 × 12 mm = 51.6 cm² | 1.24 W |
| `docs/HARDWARE_SPEC.md:848` (§2.29) | snap-on MagSafe `SOLAR-ARMOR-V1` | 7.13 W |
| `hardware/enclosure/solardeck_chassis.scad:22-24` | one recess, 45 × 15 mm | — |
| `README.md:233` specs matrix | "Bezel Strip, ~0.15W peak" | 0.15 W |

The "net-positive under 500 lux" pillar, the BOM, the CAD, and the specs matrix each assume a
different panel. Decide: **base = 0.15 W strip** (cheap, matches BOM), and mark §2.28 + Solar Armor
as *optional accessories with their own BOM blocks*.

### B6. Pogo expansion bus: descoped in prose, specified in detail elsewhere
Descoped: `docs/INDEX.md:161`, `docs/MVP_ARCHITECTURE.md:24`, `docs/HANDOFF_TO_FABLE.md:141`,
`docs/HARDWARE_SPEC.md:1116`. Still specified as real hardware:
`docs/HARDWARE_SPEC.md:1144` full 8-pin pinout + MFBL timing diagram, `:233` host channel list,
`:1065` "front 5-pin and rear 8-pin … gold-plated brass barrels" under **IP67 sealing**,
`AGENTS.md:17`, `README.md:142`, BOM `TPD4E05U06 (x4)` for pogo pins. Pick **USB-C only** and delete
§5.3's pinout into `docs/90-history/decisions.md`.

### B7. RGB "Signal Halo" is simultaneously descoped and fully specified
`docs/HARDWARE_SPEC.md:390-404` (§2.7.1) and `docs/SOFTWARE_SPEC.md:285-329` (§8) implement it;
`README.md:233` calls it a descoping win over "RGB LED & light pipe"; no BOM line item exists.
Recommendation: **keep it** — it is ~$0.30, solves the zero-watt status job in one part, and the
daemon is already specified. Add the BOM row and fix README.

### B8. Front-camera descope never propagated
`docs/HARDWARE_SPEC.md:337` is still titled "**Dual**-Camera Subsystem"; `:658` reserves "Dual
MIPI-CSI (Sony IMX708 PDAF & **IMX219**)"; `solardeck_chassis.scad:35` labels its port
"IMX219"; `docs/MVP_ARCHITECTURE.md:91` still budgets "Tier 5: Video Teleconference Mode (Front Cam)".

### B9. S2idle on CM4 is load-bearing and unverified
The 15 mW / 0.3 s pillar depends on BCM2711 `s2idle`. On Pi 4 / CM4 this is board-firmware and
kernel-version dependent and was historically unsupported. Nothing in the repo measures it.
Add to `FIRST_BOOT_CHECKLIST.md`: `cat /sys/power/state` must list `freeze`, plus a measured
`/sys/power/suspend_stats` delta. If absent, the fallback story is the RP2350 Zen mode (which is
real) and the pillar must be re-scoped.

### B10. Tests assert literals, not physics
* `firmware/rp2350/src/solardeck_sm.c:88` sets `last_wake_elapsed_us = 42000;` with the comment
  *"Simulate / record hardware wake time"* — and `test_rp2350_sm.c:44` asserts `< 300000` on that
  same constant. The <300 ms claim is therefore tautological.
* `hardware/enclosure/verify_enclosure.py` only regex-matches `CHASSIS_WIDTH = 227.0;` etc. It
  cannot see B4.
* `verify_documentation_integrity()` passes if the string `"§50"` appears in INDEX.md.
* `audit_hardware_traps.py` is a genuinely good idea — but it audits the 20-part toy netlist, so all
  7 rules pass by construction.

Ponytail-appropriate fix: keep the fast host tests, but rename them `*_contract_test.c` and move the
real numbers into `docs/SPEC_VALUES.yaml` (see §5), so tests check a single source of truth rather
than a duplicated constant.

## 3. Engineering/organizational gaps

1. **No `LICENSE`.** An "open-hardware" project with no license is legally all-rights-reserved.
   Add `CERN-OHL-S-2.0` (hardware: `hardware/`, `firmware/`) + `Apache-2.0` or `MIT` (software:
   `src/`, `scripts/`, `tools/`), and a `LICENSES/` dir with per-path mapping.
2. **No `CONTRIBUTING.md`, `CHANGELOG.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`.** For a project
   whose selling point is field sovereignty, the `SECURITY.md` (key handling, airgap threat model)
   is not optional marketing — it is the product.
3. **No BOM ↔ netlist ↔ CPL ↔ schematic cross-check.** This is the single highest-value 40-line
   script in the repo (see B1). Everything else in `verify_all.py` is cheaper than this one check.
4. **CI has no design tooling.** No `kicad-cli sch erc`, no `kicad-cli pcb drc`, no
   `openscad -o stl`, no footprint↔BOM diff, no `gerbv`/`gerber` layer sanity. The KiCad files and
   the SCAD are never even parsed. Adding `kicad-cli` would have caught "0 nets assigned".
5. **Binary production artifacts are committed** (`*.zip`, `*.stl`). Generate them in CI from the
   sources and attach to releases; committed binaries silently rot when the source changes.
6. **Docs are monolithic** — `HARDWARE_SPEC.md` 1,427 lines, `SOFTWARE_SPEC.md` 1,333. Both mix
   *specification*, *rationale*, *marketing*, and *decision history* in one file. That mixture is the
   mechanism by which D1–D20 happen.
7. **No claim-status vocabulary.** Every statement reads as equally certain: measured bench data,
   datasheet arithmetic, and fantasy ("3B LLM at zero swap thrashing") are typographically identical.
8. **No `docs/adr/`** — `docs/INDEX.md §3` is already a decision log; formalize it.
9. **`.gitignore` contains only `.pi/`.** No `__pycache__/`, `*.o`, `/tmp` build outputs, or
   generated production bundles.
10. **Attribution stamps are per-file headers, never per-claim.** `verify_documentation_integrity()`
    enforces the header string, so editors learn to copy it while editing the body. Fine as an audit
    trail, useless as a truth signal.

```
     audit-2026-10-20.md          # this file
```

Rules that keep it from drifting again:

1. **One number, one place.** Move every quantitative claim into `docs/SPEC_VALUES.yaml`
   (`ppi: 227`, `chassis_mm: [227,165,9.8]`, `battery_wh: {lifepo4: 32, liion: 37}`,
   `solar_w: {strip: 0.15, armor: 7.13}`, `hotpacks: 7`, `phases: 9`). A 60-line
   `scripts/check_docs_numbers.py` greps the docs for the literal and fails on mismatch. This kills
   D1, D2, D10, D14, D17 mechanically.
2. **Generated, never hand-maintained:** BOM tables, the INDEX cross-reference table, and the phase
   list are emitted by scripts. A hand-curated 63-row table always drifts.
3. **Delete superseded text instead of marking it "descoped".** Move it to `90-history/decisions.md`
   as `ADR-nnn: descoped X because Y`. Today the docs contain *both* the descope note *and* the full
   spec (pogo, front camera, RGB, SnapDeck), which is how a reader ends up implementing the wrong one.
4. **Every heading gets a status line**: `Status: modeled` / `measured 2026-10-2x` / `aspirational`.

## 6. What is genuinely strong (do not "fix" these)

* The dual-brain split (CM4 + RP2350 + TMUX bus isolation) is a coherent, defensible architecture.
* The BOM is real: 61 line items, plausible part numbers, distributor-sourced, arithmetically exact.
* The anti-ghosting cadence logic (`refreshd.c`) and the telemetry framing daemon are small, honest,
  testable C — exactly the right size.
* `audit_hardware_traps.py` is the right *kind* of tool; it just needs a real netlist under it.
* The decision log (INDEX §3) is genuinely good engineering archaeology — it belongs in
  `90-history/decisions.md`, not buried in an index.
* Zero broken links; every doc is stamped; the repo is clean and committed.
