## 2. New findings this pass

A. **Workflow says "11-Phase", suite is 16.** `.github/workflows/verify.yml:11` job name is
   `11-Phase System Verification`; `spec_values.verification_phases` = 16 and the suite runs 16. This is
   exactly the phase-count drift class D1 was invented to kill, and Phase 10 does not cover the workflow
   file. Small (one string) — but it is the same failure mode, alive in the same CI you trust to stop it.

B. **`verify_all.py` module docstring lists "Phase 13" twice** (lines 22 and 26) with two different
   titles ("Longevity constraints…" and "30-year longevity constraints…"). The code's `run_step` calls
   are all unique (Phase 13 runs once, via `check_longevity.py`); the docstring alone is wrong. The
   suite passes because the docstring is prose, not a check. One-line fix; the fix should be a
   docstring-count assertion so it can't regress (ponytail: add the assertion in the same edit).

C. **Production bundles are committed despite the gitignore rule that says never to.** `.gitignore:7-9`
   says `hardware/production/*.zip` and `*.stl` "are generated… never commit them", but
   `solardeck_assembly_package.zip`, `solardeck_gerbers.zip`, `solardeck_test_plan.zip`, and
   `solardeck_chassis.stl` are all tracked (87 tracked files including them). Files committed before the
   rule stay tracked. CI regenerates them and uploads as artifacts; the committed copies are the stale
   placeholders AUDIT 1 named. This contradicts both .gitignore and the CI comment.

D. **AUDIT 1's D13 (logo-keyboard/source-tree drift in AGENTS.md) is only half fixed.** The fake
   `firmware/keyboard/` and `src/drivers/` dirs referenced in the old AGENTS.md layout are gone
   (AGENTS.md:38-53 now matches reality), but `AGENTS.md:40` still lists `CHANGELOG.md` in the tree —
   **no such file exists** (`ls` confirms; also no `CODE_OF_CONDUCT.md`). AGENTS.md now claims the repo
   layout, so its own tree must be as true as the rest of it.

E. **`spec_values.json` daemon count (43) vs STATUS.md (43 listed) agree — but six daemons were folded
   into D53/D54 numbering.** STATUS.md jumps D41 → D53 (battcare) → D54 (nandcare). Nothing wrong with
   the file; a fresh reader will wonder where D42–D52 went. One sentence in STATUS.md would close it.

F. **Gates: 11, all G1–G10 aspirational, only G11 `specified`.** The pillars (P1, P2, P3, P5, E2, E4)
   that carry the product's identity have zero measured support. Nothing here is new — AUDIT 4 F3 said
   it harder — but the phrasing that stays accurate is: *the top ten acceptance gates are all
   unmeasured, and the gate numbering intentionally skips past the one gate that is testable today.*

## 4. What is genuinely strong (do not "fix")

- The 16-phase runner recomputes numbers from `spec_values.json` rather than trusting prose — the exact
  cure AUDIT 3 prescribed, and it is *wired into CI* (not just local).
- `solardeck_regs.h` as a single contract with `_Static_assert` layout guards + wire test is the
  strongest artifact in the repo.
- REGULATORY.md's "no certificate row at filed/granted = no shipment" rule, and its honest `not started`
  column, is the right posture.
- The ADR log (24 entries) records *reversals* — TMUX1575, DSI video, piezo, solar, pogo — which is the
  property that makes the design credible to an outside reviewer.

## 5. What an owner should do next (in order of leverage)

1. **Answer the 2034 question.** Socketed CM4 with CM5 escape: credible 30-year plan or a 10-year device
   with a 30-year story? AUDIT 4 asked; nothing has decided. This is a positioning decision, not
   engineering, and it gates every marketing claim.
2. **Buy the dev kit; measure three numbers.** S2idle power (→G3), wake latency (→G1), keystroke
   latency (→G2). Until then zero gates can be promoted out of `aspirational`, and the three pillars the
   product is judged on stay claims.
3. **Start UN 38.3** (cells + test house, ~6–10 weeks, longest lead) the day a pack design freezes.
4. **Cut the daemon list.** 43 specified, 2 implemented. The 30-year maintenance liability argument
   (AUDIT 4) still stands; nobody has made the cut-to-~8 case.
5. **Fix the trivial four** — workflow name (A), docstring dup (B), untrack the stale zips/stl (C),
   AGENTS.md CHANGELOG line (D). All together: under an hour, no design risk.

## 6. Bottom line

Four audits in, the repo has done the hard, unglamorous work: it now fails loudly when numbers disagree,
states what is unmeasured in bold, and documents its reversals. The remaining gap is not verbiage — it is
three measured numbers, one battery certification, and an honest answer about the CM4's twenty-two-year
hole. The next audit should start with a soldering iron, not a `git log`.
